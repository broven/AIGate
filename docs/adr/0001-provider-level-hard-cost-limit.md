# Provider 级硬成本上限

Cloudflare Workers AI 的免费额度（10,000 neurons/天，约 $0.11）是**账号级**共享的，而 AIGate 的调度单元是 Model Deployment。为避免"每个 Deployment 各设一份额度导致总额超支数倍"这种比没有上限更危险的假安全感，Cost Limit 挂在 **Provider** 上：达到上限后该 Provider 的全部 Deployment 一并退出候选，且是**硬关**——不降级、不告警放行，因为会继续花钱的上限等于没有上限。

## Considered Options

- **Deployment 级上限**：粒度更细，但与账号级额度池语义错配（N 个模型各设 $0.11 → 实际可花 N×$0.11），且 Deployment 是同步过程自动增删的派生数据，人工配置会被冲掉。想限制单个模型，已有 `blacklisted` 开关。
- **降级为末位兜底**：可用性更好，但上限变成软的，用户会在看到"已达上限"的同时继续被扣费。

## Consequences

- 上限留空（`null`）表示不限——"用完免费额度后继续使用"不是第二种模式，而是不设上限。配置面因此只有一个数字。
- CF 独占模型（`@cf/...`）在撞上限后整体不可用，返回 `503` 并在 body 中说明重置时间；不用 `404`，因为模型存在、只是暂不可调度。
- 成本只有请求完成后才知道，因此允许超调。超调的成因是"在途并发 × 单次成本"，故用**绝对预留**（在途请求数 × 该 Deployment 输出单价 × 保守输出 token 数）而非百分比安全边际——后者在 $0.11 这种小额度下比它要防的超调小一个数量级。
